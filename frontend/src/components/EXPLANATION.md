# EXPLANATION — frontend/src/components/

## Purpose

The `components/` folder contains every reusable UI piece in the application.
Components are organised by concern, not by page — a component that appears on
the dashboard and the public booking page lives in `common/`, not in a page-specific
folder.

There are six sub-folders:
- `ui/` — shadcn/ui generated components (never hand-edited)
- `layout/` — structural shells (dashboard wrapper, sidebar, topbar)
- `common/` — generic, domain-agnostic components (spinner, empty state, error)
- `booking/` — the 5-step customer booking wizard components
- `bookings/` — owner and customer booking list/detail components
- `services/`, `staff/`, `slots/`, `analytics/`, `admin/` — domain-specific components

This explanation focuses on the `ui/` components you'll use constantly, how they're
installed, and the exact patterns for using each one.

---

## How it works

### The `ui/` folder — shadcn/ui Components

This folder contains components generated by the shadcn CLI. **You should never
hand-edit files in this folder.** Running `npx shadcn-ui@latest add button` again
would overwrite your changes.

If you need to customise a component beyond what its props allow, copy it out of
`ui/` into `common/` and modify it there.

#### How to install shadcn components

```bash
# Install the shadcn CLI (one time)
npx shadcn-ui@latest init

# Add individual components as needed
npx shadcn-ui@latest add button
npx shadcn-ui@latest add input
npx shadcn-ui@latest add card
npx shadcn-ui@latest add dialog
npx shadcn-ui@latest add select
npx shadcn-ui@latest add badge
npx shadcn-ui@latest add calendar
npx shadcn-ui@latest add skeleton
npx shadcn-ui@latest add table
npx shadcn-ui@latest add toast
npx shadcn-ui@latest add form
npx shadcn-ui@latest add label
npx shadcn-ui@latest add separator
```

Each command creates a file in `src/components/ui/` and installs any required
peer dependencies. The `components.json` file tracks which components are installed
and their configuration.

### `Button` — The Most Used Component

```jsx
// src/components/ui/button.jsx (generated — do not edit)
import { cn } from '@/lib/utils';
import { cva } from 'class-variance-authority';

const buttonVariants = cva(
  // Base classes applied to every button
  'inline-flex items-center justify-center rounded-md text-sm font-medium transition-colors focus-visible:outline-none focus-visible:ring-2 disabled:pointer-events-none disabled:opacity-50',
  {
    variants: {
      variant: {
        default:     'bg-primary text-primary-foreground hover:bg-primary/90',
        destructive: 'bg-destructive text-destructive-foreground hover:bg-destructive/90',
        outline:     'border border-input bg-background hover:bg-accent',
        ghost:       'hover:bg-accent hover:text-accent-foreground',
        link:        'text-primary underline-offset-4 hover:underline',
      },
      size: {
        default: 'h-10 px-4 py-2',
        sm:      'h-9 rounded-md px-3',
        lg:      'h-11 rounded-md px-8',
        icon:    'h-10 w-10',
      },
    },
    defaultVariants: { variant: 'default', size: 'default' },
  }
);

const Button = React.forwardRef(({ className, variant, size, ...props }, ref) => (
  <button
    className={cn(buttonVariants({ variant, size, className }))}
    ref={ref}
    {...props}
  />
));
```

**Usage in BookMySlot:**

```jsx
import { Button } from '@/components/ui/button';

// Default (primary, indigo)
<Button onClick={handleBooking}>Confirm Booking</Button>

// Destructive (red) — for dangerous actions
<Button variant="destructive" onClick={handleCancel}>Cancel Booking</Button>

// Outline — for secondary actions
<Button variant="outline" onClick={handleBack}>← Back</Button>

// Ghost — for subtle actions (e.g., in sidebars)
<Button variant="ghost" className="w-full justify-start">
  <CalendarIcon className="mr-2 h-4 w-4" /> Slots
</Button>

// With loading state
<Button disabled={isLoading}>
  {isLoading ? <Spinner className="mr-2 h-4 w-4" /> : null}
  {isLoading ? 'Booking...' : 'Confirm Booking'}
</Button>

// Icon only
<Button variant="ghost" size="icon">
  <XIcon className="h-4 w-4" />
</Button>
```

**The `cva` function (class-variance-authority)** generates the correct Tailwind
class string for each variant/size combination at runtime. It's what makes
`<Button variant="destructive">` work without writing conditional className logic.

### `Card` — The Primary Container

`Card` is the visual container for almost every section of the UI. The owner
dashboard, booking confirmation, service items — all use Card.

```jsx
import { Card, CardHeader, CardTitle, CardDescription, CardContent, CardFooter } from '@/components/ui/card';

// Stat card on the dashboard overview
<Card>
  <CardHeader className="flex flex-row items-center justify-between space-y-0 pb-2">
    <CardTitle className="text-sm font-medium text-muted-foreground">Bookings Today</CardTitle>
    <CalendarIcon className="h-4 w-4 text-muted-foreground" />
  </CardHeader>
  <CardContent>
    <div className="text-2xl font-bold">12</div>
    <p className="text-xs text-muted-foreground">+3 from yesterday</p>
  </CardContent>
</Card>

// Service listing card on the public booking page
<Card
  className={cn('cursor-pointer transition-all', isSelected && 'border-primary ring-2 ring-primary')}
  onClick={() => onSelect(service)}
>
  <CardContent className="p-4">
    <div className="flex justify-between items-start">
      <div>
        <h3 className="font-semibold">{service.name}</h3>
        <p className="text-sm text-muted-foreground">{service.durationMinutes} min</p>
      </div>
```

The sub-components (`CardHeader`, `CardTitle`, `CardContent`, `CardFooter`) are

typography without you having to remember the pixel values.

### `Badge` — Status Indicators

Badges display short, colour-coded labels. Used heavily for booking status
(`confirmed`, `cancelled`, `completed`) and service/staff active status.

```jsx
import { Badge } from '@/components/ui/badge';

// Status badge — dynamically pick variant based on booking status
const StatusBadge = ({ status }) => {
  const variantMap = {
    confirmed:  'default',     // indigo/primary
    completed:  'secondary',   // grey
    cancelled:  'destructive', // red
  };
  return <Badge variant={variantMap[status]}>{status}</Badge>;
};

// Usage in BookingTable.jsx
<TableCell><StatusBadge status={booking.status} /></TableCell>

// Active/inactive indicator on services
<Badge variant={service.isActive ? 'default' : 'outline'}>
  {service.isActive ? 'Active' : 'Inactive'}
</Badge>
```

### `Dialog` — Modal Overlays

`Dialog` is used for all forms that appear as overlays: creating a service,
adding a staff member, confirming a cancellation, blocking a slot.

```jsx
import {
  Dialog,
  DialogTrigger,
  DialogContent,
  DialogHeader,
  DialogTitle,
  DialogDescription,
  DialogFooter,
} from '@/components/ui/dialog';

// ServiceForm inside a Dialog — controlled with useState
const [open, setOpen] = useState(false);

<Dialog open={open} onOpenChange={setOpen}>
  <DialogTrigger asChild>
    <Button onClick={() => setOpen(true)}>+ New Service</Button>
  </DialogTrigger>

  <DialogContent className="sm:max-w-[480px]">
    <DialogHeader>
      <DialogTitle>Create Service</DialogTitle>
      <DialogDescription>
        Add a new service that customers can book.
      </DialogDescription>
    </DialogHeader>

    {/* Form content */}
    <div className="grid gap-4 py-4">
      <div className="grid gap-2">
        <Label htmlFor="name">Service Name</Label>
        <Input id="name" value={name} onChange={(e) => setName(e.target.value)} placeholder="e.g. Haircut & Styling" />
      </div>
      <div className="grid grid-cols-2 gap-4">
        <div className="grid gap-2">
          <Label htmlFor="duration">Duration (min)</Label>
          <Select value={duration} onValueChange={setDuration}>
            <SelectTrigger><SelectValue placeholder="Select..." /></SelectTrigger>
            <SelectContent>
              {[15, 30, 45, 60, 90, 120].map(d => (
                <SelectItem key={d} value={String(d)}>{d} min</SelectItem>
              ))}
            </SelectContent>
          </Select>
        </div>
        <div className="grid gap-2">
          <Label htmlFor="price">Price (₹)</Label>
          <Input id="price" type="number" value={price} onChange={(e) => setPrice(e.target.value)} min="0" />
        </div>
      </div>
    </div>

    <DialogFooter>
      <Button variant="outline" onClick={() => setOpen(false)}>Cancel</Button>
      <Button onClick={handleSubmit} disabled={isLoading}>
        {isLoading ? 'Creating...' : 'Create Service'}
      </Button>
    </DialogFooter>
  </DialogContent>
</Dialog>
```

**`asChild` prop:** When you use `asChild` on `DialogTrigger`, it passes the
dialog-trigger behaviour to its child (`<Button>`) instead of rendering an extra
wrapper element. This keeps the DOM clean and the button fully styleable.

**Controlled vs. uncontrolled:** Managing `open` with `useState` gives you full
control over when the dialog opens and closes — important when you need to close
it programmatically after a successful API call.

### `Calendar` — Date Picker for Booking Flow

The shadcn Calendar is built on `react-day-picker` and is used in step 3 of the
booking wizard (date selection) and in the slot blocking form.

```jsx
import { Calendar } from '@/components/ui/calendar';
import { useState } from 'react';

// In SlotPicker.jsx — customer selects a date to see available slots
const [selectedDate, setSelectedDate] = useState(null);

<Calendar
  mode="single"
  selected={selectedDate}
  onSelect={(date) => {
    setSelectedDate(date);
    if (date) fetchAvailableSlots(format(date, 'yyyy-MM-dd')); // using date-fns
  }}
  disabled={(date) => {
    const today = new Date();
    today.setHours(0, 0, 0, 0);
    const maxDate = new Date();
    maxDate.setDate(today.getDate() + 30); // max 30 days ahead (from PRD)

    return date < today || date > maxDate;
  }}
  className="rounded-md border"
/>
```

The `disabled` callback receives each calendar day as a Date object and returns
`true` to disable it (grey it out, make it unclickable). This implements the PRD
rule that bookings can only be made for today or within 30 days.

**`format(date, 'yyyy-MM-dd')` from date-fns** converts the JavaScript Date object
to the `YYYY-MM-DD` string format the API expects. Install date-fns:
```bash
npm install date-fns
```

### `Toast` — Non-Blocking Notifications

Toasts are the success/error notification system. They appear as small overlays
at the bottom-right of the screen and disappear automatically.

```jsx
// How to use toast in any component
import { useToast } from '@/components/ui/use-toast';

const { toast } = useToast();

// Success toast
toast({
  title: 'Booking confirmed!',
  description: `Your booking reference is ${bookingRef}`,
});

// Error toast
toast({
  title: 'Something went wrong',
  description: error.message,
  variant: 'destructive',
});

// 409 conflict — the most important use case in BookMySlot
if (err.response?.status === 409) {
  toast({
    title: 'Slot just taken',
    description: 'Someone else just booked this slot. Refreshing available times...',
    variant: 'destructive',
  });
  await refetchSlots(); // reload slot list without losing form data
}
```

`<Toaster />` is mounted once in `main.jsx` and `useToast()` communicates with it
via an internal event system. Any component can call `toast()` without needing to
know where `<Toaster>` is in the tree.

### `Skeleton` — Loading State Placeholders

Skeletons are animated grey boxes that match the approximate shape of the content
that will appear. They make the app feel faster by showing structure before data loads.

```jsx
import { Skeleton } from '@/components/ui/skeleton';

// PageSkeleton for the services list while loading
const ServiceListSkeleton = () => (
  <div className="space-y-3">
    {[1, 2, 3].map((i) => (
      <Card key={i}>
        <CardContent className="p-4">
          <div className="flex justify-between">
            <div className="space-y-2">
              <Skeleton className="h-4 w-[200px]" />   {/* service name */}
              <Skeleton className="h-3 w-[120px]" />   {/* duration */}
            </div>
            <Skeleton className="h-6 w-[60px]" />       {/* price */}
          </div>
        </CardContent>
      </Card>
    ))}
  </div>
);

// Usage in ServicesPage.jsx
{isLoading ? <ServiceListSkeleton /> : <ServiceTable services={services} />}
```

The `h-*` and `w-*` classes control the skeleton's height and width. Match them
to the approximate dimensions of the real content for the best visual effect.

Used in the owner bookings list, services list, admin business table.

```jsx
import {

// BookingTable.jsx
<Table>

    </TableRow>
  </TableHeader>
  <TableBody>
    {bookings.map((booking) => (
      <TableRow
        key={booking.id}
        className="cursor-pointer hover:bg-muted/50"
        onClick={() => setSelectedBooking(booking)}
      >
        <TableCell className="font-mono text-sm">{booking.bookingRef}</TableCell>
        <TableCell>
          <div className="font-medium">{booking.customerName}</div>
          <div className="text-sm text-muted-foreground">{booking.customerEmail}</div>
        </TableCell>
        <TableCell>{booking.serviceName}</TableCell>
        <TableCell>
          <div>{booking.date}</div>
          <div className="text-sm text-muted-foreground">{booking.startTime} – {booking.endTime}</div>
        </TableCell>
        <TableCell><StatusBadge status={booking.status} /></TableCell>
        <TableCell className="text-right">
          {booking.status === 'confirmed' && (
            <Button
              variant="ghost"
              size="sm"
              onClick={(e) => { e.stopPropagation(); handleCancel(booking.id); }}
            >
              Cancel
            </Button>
          )}
        </TableCell>
      </TableRow>
    ))}
  </TableBody>
</Table>
```

Note `e.stopPropagation()` on the Cancel button's click — without it, clicking
Cancel would also trigger the row's `onClick` (which opens the detail panel).
`stopPropagation` prevents the click from bubbling up to parent elements.

### `Form`, `Label`, `Input` — Controlled Forms

shadcn/ui's `Form` components integrate with React Hook Form for validation. For
simpler forms in BookMySlot, you can use `Label` and `Input` directly with
`useState`:

```jsx
import { Label } from '@/components/ui/label';
import { Input } from '@/components/ui/input';

// CustomerForm.jsx — step 4 of booking wizard
const [name, setName] = useState('');
const [email, setEmail] = useState('');
const [phone, setPhone] = useState('');
const [errors, setErrors] = useState({});

const validate = () => {
  const newErrors = {};
  if (!name.trim()) newErrors.name = 'Name is required';
  if (!/^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(email)) newErrors.email = 'Valid email required';
  if (!/^[6-9]\d{9}$/.test(phone)) newErrors.phone = 'Valid Indian mobile number required';
  setErrors(newErrors);
  return Object.keys(newErrors).length === 0;
};

<div className="grid gap-4">
  <div className="grid gap-2">
    <Label htmlFor="name">Full Name</Label>
    <Input
      id="name"
      value={name}
      onChange={(e) => setName(e.target.value)}
      placeholder="Rohan Kulkarni"
      className={errors.name ? 'border-destructive' : ''}
    />
    {errors.name && <p className="text-sm text-destructive">{errors.name}</p>}
  </div>

  <div className="grid gap-2">
    <Label htmlFor="email">Email Address</Label>
    <Input
      id="email"
      type="email"
      value={email}
      onChange={(e) => setEmail(e.target.value)}
      placeholder="rohan@example.com"
    />
    {errors.email && <p className="text-sm text-destructive">{errors.email}</p>}
  </div>

  <div className="grid gap-2">
    <Label htmlFor="phone">Mobile Number</Label>
    <Input
      id="phone"
      type="tel"
      value={phone}
      onChange={(e) => setPhone(e.target.value)}
      placeholder="9876543210"
      maxLength={10}
    />
    {errors.phone && <p className="text-sm text-destructive">{errors.phone}</p>}
  </div>
</div>
```

The `htmlFor` on `<Label>` must match the `id` on `<Input>`. This is an
accessibility requirement — clicking the label focuses the input, and screen
readers announce the label when the input is focused.

### `ProtectedRoute` — Route-Level Auth Guard

```jsx
// src/components/ProtectedRoute.jsx
import { useContext } from 'react';
import { Navigate } from 'react-router-dom';
import { AuthContext } from '@/context/AuthContext';

export const ProtectedRoute = ({ children, role }) => {
  const { user, isAuthenticated } = useContext(AuthContext);

  if (!isAuthenticated) {
    return <Navigate to="/login" replace />;
  }

  if (role && user.role !== role) {
    return <Navigate to="/" replace />;  // redirect to home if wrong role
  }

  return children;
};

// Usage in AppRouter.jsx
<Route
  path="/dashboard/*"
  element={
    <ProtectedRoute role="business_owner">
      <DashboardLayout />
    </ProtectedRoute>
  }
/>
<Route
  path="/admin"
  element={
    <ProtectedRoute role="super_admin">
      <AdminPage />
    </ProtectedRoute>
  }
/>
```

`replace` on `<Navigate>` prevents the login page from being added to the browser
history stack — pressing Back after a redirect doesn't loop you back to login.

## Key Decisions

**Why are all shadcn components in `ui/` and never in other subfolders?**

Running `npx shadcn-ui@latest add` always writes to `components/ui/`. If you put
custom components in `ui/`, re-running the CLI would overwrite them. The strict
separation means you can safely re-run `npx shadcn-ui@latest add <component>`
to update a component without worrying about losing custom code.

**Why `variant` prop instead of conditional className logic?**

```jsx
// ❌ Fragile — className logic scattered everywhere
<button className={isDestructive ? 'bg-red-500 ...' : 'bg-indigo-500 ...'}>

// ✅ Readable and consistent
<Button variant={isDestructive ? 'destructive' : 'default'}>
```

Variants are self-documenting. Anyone reading the code knows exactly which visual
style is intended without having to reverse-engineer Tailwind classes.

**Why no `<form>` HTML element?**

The system prompt for this project explicitly states: never use HTML `<form>` tags
in React Artifacts. Use `onClick` handlers on `<Button>` elements instead.
This avoids the default form submission behaviour (page reload) which conflicts
with React's state management.

## What you should learn from this

1. **shadcn/ui is copied code, not a package.** This means you can read it,
   understand it, and modify it. Open `src/components/ui/button.jsx` and read it.
   Understanding one shadcn component means understanding them all.

2. **`cn()` is essential.** Every time you conditionally apply classes or allow
   a caller to extend a component's classes, use `cn()`. Without `twMerge`, you'd
   get conflicting Tailwind classes that produce unpredictable styles.

3. **Skeletons before spinners.** A skeleton that matches your layout's shape is
   far more polished than a generic spinner. It tells the user "content is loading
   here" instead of "something is happening somewhere."

4. **`e.stopPropagation()` in nested click handlers** is a common React gotcha.
   If a button is inside a clickable row, you need to stop the button's click from
   triggering the row's click. Learn this pattern — you'll use it constantly.

5. **Accessibility fundamentals:** `htmlFor` matches `id`, `aria-label` for
   icon-only buttons, `disabled` on form elements while loading. These are not
   optional — they make the app usable for screen reader users and are expected
   by hiring managers reviewing your code.
