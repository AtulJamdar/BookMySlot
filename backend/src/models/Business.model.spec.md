# SPEC — backend/src/models/Business.model.js

## File Role
Defines the Mongoose schema and model for a tenant business entity, including the pre-save hook that auto-generates a URL-safe slug from the business name and the `workingHours` sub-schema used in slot generation.

---

## Dependencies

```js
import mongoose from 'mongoose';            // npm — schema + model factory
import { slugify } from '../utils/slugify.js'; // internal — name → slug conversion
import { BUSINESS_CATEGORIES } from '../utils/constants.js'; // internal — category enum
```

---

## Exports

### Default export: `Business` (Mongoose Model)

**Pre-save hook (side effect — runs automatically before every `.save()`):**
- If `name` is modified AND `slug` has not been manually set, calls `slugify(this.name)` to generate a slug candidate
- Does NOT check slug uniqueness here — uniqueness is enforced by the index; the service layer must handle `E11000` on slug collision and suggest an alternative (e.g., `sunshine-salon-pune`)
- Hook must use `function` keyword

## Data Contracts

### Sub-schema: `WorkingHoursEntry`

| Field   | Type   | Required | Validation                                                              |
|---------|--------|----------|-------------------------------------------------------------------------|
| `day`   | String | ✅       | enum: `['monday','tuesday','wednesday','thursday','friday','saturday','sunday']` |
| `start` | String | ✅       | pattern: `/^([01]\d|2[0-3]):[0-5]\d$/` (HH:MM 24h)                    |
| `end`   | String | ✅       | pattern: `/^([01]\d|2[0-3]):[0-5]\d$/`; must be after `start` — validated in service, not model |

| Field           | Type                   | Required | Default | Validation / Notes                                              |
|-----------------|------------------------|----------|---------|-----------------------------------------------------------------|
| `ownerId`       | ObjectId               | ✅       | —       | ref: `'User'`; the business_owner user linked to this business  |
| `name`          | String                 | ✅       | —       | minLength: 2, maxLength: 100, trim: true                        |
| `slug`          | String                 | ✅       | —       | unique, lowercase, URL-safe; generated by pre-save hook         |
| `category`      | String                 | ✅       | —       | enum from `BUSINESS_CATEGORIES`: `['salon','clinic','coaching','other']` |
| `city`          | String                 | ✅       | —       | minLength: 2, maxLength: 60, trim: true                         |
| `phone`         | String                 | ✅       | —       | pattern: `/^[6-9]\d{9}$/`                                       |
| `description`   | String                 | ❌       | null    | maxLength: 500                                                  |
| `workingHours`  | [WorkingHoursEntry]    | ❌       | `[]`    | array of working day configs; empty = no hours set             |

| `isActive`      | Boolean                | ❌       | `true`  | false = suspended; public booking page returns 403              |
| `createdAt`     | Date                   | auto     | —       | via `timestamps: true`                                          |
| `updatedAt`     | Date                   | auto     | —       | via `timestamps: true`                                          |

### Indexes

| Fields   | Options          | Reason                                                    |
|----------|------------------|-----------------------------------------------------------|
| `slug`   | `unique: true`   | Enforces global slug uniqueness; speeds `/b/:slug` lookup |
| `isActive` | standard       | Speeds Super Admin filtered queries                       |

---

## Rules & Constraints

1. `slug` must be globally unique across all businesses. The pre-save hook generates it, but the service must catch `E11000` and suggest an alternative slug with the city suffix (e.g., `sunshine-salon` → `sunshine-salon-pune`).
2. `slug` must be URL-safe: lowercase, alphanumeric, hyphens only. No spaces, no uppercase, no special characters. The `slugify()` utility handles this.
3. When `isActive` is set to `false` by a Super Admin, the public booking endpoint `GET /businesses/:slug` must return `403`. This check is in the controller/service, not the model.
4. `bufferMinutes` is applied between consecutive appointment windows during slot generation in `slot.service.js`. The model stores the value only.
5. `workingHours` is the **business-level default**. Individual staff members may override it with their own `workingHours` array. The slot service resolves this at query time.
6. A Business document is created atomically alongside its owner User document in `auth.service.js` using a Mongoose session transaction. The model must support session-aware writes.

---

## Do NOT

- Do NOT validate that `end > start` in `WorkingHoursEntry` inside the model — do it in the service layer or with a custom validator that can be tested independently.
- Do NOT check slug uniqueness in the pre-save hook — let the unique index handle it and catch `E11000` in the service.
- Do NOT soft-delete businesses from this model — suspension is handled by toggling `isActive` via the Super Admin service, and hard deletion is an admin-only operation outside normal flow.
- Do NOT expose `ownerId` on public API responses — the `BusinessPublic` shape (defined in the controller) omits it.
